# 任务五：日志排查演练记录

本文件记录任务五中故意制造的三类错误及排查过程，对应实验报告"任务 5　日志排查、ApiFox 准备与 AI 代码甄别"。

## 1. 参数名拼写错误（ParameterBindingException）

- 操作：将 `StudentMapper.xml` 中 `#{studentNo}` 改为 `#{studentno}`。
- 现象：运行 `testAddAndDelete` 报 `ReflectionException: There is no getter for property named 'studentno' in 'class com.lab.student.entity.Student'`。
- 结论：`#{}` 内的属性名必须与实体类属性完全一致（含大小写），写错会在反射绑定阶段抛出异常。

## 2. resultMap 列名错误（结果静默为 null）

- 操作：将 resultMap 中 `column="stu_class"` 改为错误拼写 `stu_classs`。
- 现象：程序不报错，但打印结果中 `stuClass=null`。
- 结论：resultMap 列名错误不会抛异常，只导致对应属性静默为 null，是最易忽略的隐性 bug，需对照 SQL 日志与打印结果排查。

## 3. 删除 useGeneratedKeys（主键不回填）

- 操作：删除 `<insert>` 上的 `useGeneratedKeys="true" keyProperty="studentId"`。
- 现象：新增成功（Updates: 1），但打印 `回填主键 studentId = null`。
- 结论：没有 useGeneratedKeys 时自增主键不写回实体对象，后续按主键操作会失效；演练还导致插入数据无法按主键删除而残留，印证了连锁影响。
